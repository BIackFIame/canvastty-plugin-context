# CanvasTTY Context

> **Нужно ядро CanvasTTY с plugin API v2** (сервисы плагинов, участие в запуске, окружения сессий, решающие хуки, инструменты плагинов и действия на карточках, `launch.delegable` и `cards:decorate`): ближайший выпуск после 1.7.0. В CanvasTTY 1.7.0 и раньше этих точек расширения нет, поэтому установка там не пройдёт проверку манифеста.

Правила проектов для агентов в [CanvasTTY](https://github.com/howdeploy/CanvasTTY): соглашения, которые иначе
приходится повторять в каждом запросе, хранятся по проектам и передаются Claude Code, Codex, Grok, Qwen Code или Pi при запуске с Send rules.

- **Правила** для вас (все проекты), по умолчанию, для организации, проекта или сохранённой задачи; у каждого есть
  категория (дизайн, архитектура, стиль кода, безопасность, тесты, …), ключ и текст или JSON. Более конкретное правило
  с тем же ключом сильнее: инструкция самого запуска → задача → проект → организация → пользователь → по умолчанию; в
  одной области ваше правило сильнее импортированного. Правила безопасности и зависимостей не отфильтровываются и не
  обрезаются.
- **Импорт из файлов проекта** — читаются, когда нужны правила (без фонового сканирования): `AGENTS.md`, `CLAUDE.md`,
  `GEMINI.md`, `CONTRIBUTING.md`, `.cursorrules`, `.windsurfrules`, `.github/copilot-instructions.md`, правила Cursor
  с `alwaysApply: true`, разделы README о разработке, тестах и стиле кода, `.editorconfig`, JSON-конфиги Prettier/ESLint
  и CSS-переменные выбранных блоков тем. JavaScript-конфиги не запускаются; YAML-конфиги видны, но не разбираются.
  Чтение только внутри папки проекта (без ссылок, до 64 КБ на файл, 256 КБ всего). **Переопределить** превращает
  импортированную строку в ваше редактируемое правило с тем же ключом.
- **Токены дизайна и проверяемые соглашения**: заготовки для цветов, типографики, отступов, радиусов и цветов
  компонентов и JSON-шаблоны `validate.*` (запрещённые цвета и пары цветов, настройки форматтера, имена файлов,
  зависимости), форма которых проверяется при сохранении.
- **Память проекта**: агент может предложить долговечный факт через `remember` и искать одобренные факты через
  `recall`. Память привязана к зарегистрированному проекту и хранится в закрытой папке данных плагина вне проекта;
  секреты маскируются до сохранения. Предложения агента по умолчанию ждут одобрения человека. В Настройках можно отредактировать, одобрить
  или удалить запись, а также отключить одобрение для проекта. У записи указаны автор и дата. При запуске передаётся
  только одобренная память размером до 4 КиБ (либо до меньшего лимита аргумента CLI).

## Как правила попадают к агенту

Доверьтесь нативному коду плагина (Настройки → Плагины), затем в окне запуска откройте **Дополнительно → Use CanvasTTY
Context**:

| Поле | Смысл |
|:--|:--|
| Send rules | Включено по умолчанию; выключено — для этого запуска ничего не передаётся |
| Saved task | Добавляет правила задачи (задачи подписаны проектом) |
| Only this category | Только одна категория (безопасность и зависимости — всегда) |
| Instruction for this launch | Ещё одно правило, сильнее всех остальных, только для этого запуска |

Правила для папки карточки собираются при каждом старте (и при перезапуске, и при восстановлении), поэтому изменённое
правило или файл действует со следующего старта. Как их получает каждый поддерживаемый агент:

| Агент | Как | Размер |
|:--|:--|:--|
| Claude Code | файл запуска, `--append-system-prompt-file` (добавляется к системному промпту) | 24 КБ |
| Codex | `-c developer_instructions="…"` (рядом с `AGENTS.md`) | 1024 символа одним аргументом |
| Grok | `--rules "…"` | 1024 символа |
| Qwen Code | [`--append-system-prompt "…"`](https://github.com/QwenLM/qwen-code-docs/blob/main/website/content/en/users/features/headless.md) для этого запуска | 1024 символа |
| Pi | [`--append-system-prompt "…"`](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/cli.md) для этого запуска | 1024 символа |

Правила, которые не помещаются, пропускаются целиком, и предпросмотр показывает, сколько; если не помещается правило
безопасности, зависимостей или инструкция запуска, запуск отклоняется с причиной. Qwen Code и Pi получают инструкции
одноразовым флагом; текст для Pi начинается с префикса, чтобы не выглядеть как путь к файлу. Плагин не меняет пользовательские
конфиги и разрешения CLI. У остальных агентов карточка показывает **Rules not delivered** и способ через `rules_for`/`recall`,
пока безопасный канал запуска не будет подтверждён.

CanvasTTY не принимает от плагинов аргументы, задающие его собственные одобрения, песочницу или хуки, поэтому аргумент
для Codex и Grok оценивается по форме так же: правило может сказать «никогда не обходи проверку», но правила, текст
которых начинается как такая настройка (`sandbox_mode=…`) или как флаг командной строки, отклоняются с причиной;
переформулируйте первое правило.

## Оркестраторы

`canvastty-context__rules_for` (оркестраторы и субагенты) отвечает, какие правила действуют для папки (по умолчанию —
своей), при желании для сохранённой задачи или одной категории: правила по порядку, точный текст и `launchOptions`
для `spawn_agent`, чтобы субагент Claude Code, Codex, Grok, Qwen Code или Pi получил их при запуске. Параметры запуска объявлены
делегируемыми (`launch.delegable`; необъявленные CanvasTTY в `spawn_agent` не принимает): они выбирают только, какие правила добавить в запрос агента, и никогда не дают разрешений.

## Серверы и контейнеры

Правила передаются вместе с запуском (файлом для Claude Code, аргументом для Codex, Grok, Qwen Code и Pi). На этом компьютере и в
worktree CanvasTTY Environments они доходят до агента. Серверы (ssh) и контейнеры не передают файлы запуска и локальные
пути, поэтому окно там с включённым **Send rules** запускается без правил и получает значок *Rules not delivered*
(«правила проекта не доставлены на этот сервер/в контейнер»); если правила нужны, дайте агенту текст `rules_for` в
запросе. Среда другого плагина считается так же: плагин не может знать, передаёт ли она запуск. Для значка нужно
разрешение `cards:decorate`.

## Хранение

Проекты, задачи, правила и политика одобрения хранятся в `rules/rules.json` (закрытый файл) в папке данных плагина,
отдельно от настроек. Память проекта хранится в `memory/<хеш-идентичности-проекта>.json` в той же закрытой папке данных,
вне доступной агенту папки проекта. Старый `.canvastty/memory.json` импортируется один раз: все записи ждут одобрения,
а последующие изменения старого файла не могут одобрить их. Изменения правил сверяются с ревизией, поэтому второй
писатель в ту же папку получает отказ, а не перезаписывает данные (брошенная блокировка перехватывается через 30 с).
Удаление данных плагина удаляет и его правила, и одобренную память; старые файлы внутри проекта не затрагиваются.
Между службой и CanvasTTY кадр не больше 1 МиБ, вызов хоста завершается ошибкой через 30 с или сверх 64
одновременных, ждущие события и журнал ограничены 8 МиБ.

## Что не перенесено из CanvasTTY #68

Обучение на исправлениях, классы данных (нижние границы и потолки маршрутов — в ядре CanvasTTY нет класса данных
маршрута, с которым сравнивать), проверка снимков капсул, обновление контекста ACP перед каждой задачей, предпросмотр
маршрута запуска по хостам и разбор YAML-конфигов.

## Сборка и тесты

```
npm install        # или ESBUILD=/path/to/esbuild
npm run build      # собирает services/context.mjs и settings/context.js, проставляет coreFiles
npm test           # с CANVASTTY_REPO=/path/to/CanvasTTY — ещё валидатор, супервизор и конвейер запуска CanvasTTY
```
